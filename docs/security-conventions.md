# 安全与脱敏规范

本仓库是**公开**的，而它处理的东西天然带敏感标识。这份文档把"什么能进仓库、
什么不能、以及**怎么保证它真的没进**"写成可执行的规则。

> 为什么值得单独一份文档，而不是散在各文件的注释里：注释只在**你正好打开那个文件时**
> 才起作用，而泄漏是**跨文件**的 —— 它发生在"新写一个工具、顺手把真实域名写进默认值"
> 那一刻。规则得有一个能被指向的地址。

---

## 1. 标识分类：先判断，再决定放哪

写任何配置/文档/测试前，先按这张表分类。

**判据是**："贴进公开仓库，会不会让别人获得你的能力、或者把行为关联到你" ——
会 ⇒ 不进仓库；不会 ⇒ 可以留，但要写清理由。

| 分类 | 判据 | 本项目的具体例子 | 放哪 |
|---|---|---|---|
| 🔴 **秘密** | 拿到就能用 | CF Worker Admin Token、CF 账户级 API Token（`cfat_…`）、账号密码、session token | 只进 `.env` / 台账；**代码里默认空**，缺失时启动阶段报错 |
| 🟠 **基础设施标识** | 能定位到你的基础设施 | **Worker 子域**（`<worker>.<sub>.workers.dev`）、**收信域名**、出口 IP、本机绝对路径、具体账号地址 | 不进仓库；本地值放 `.env`；**文档用占位符** |
| 🟡 **风控标识** | 能把行为和某个身份关联起来 | 出口 IP（既是 🟠 也是 🟡）、邮箱地址、代理服务商 | 同上；出口 IP 只在终端打印，**绝不贴进 issue/对话** |
| 🟢 **公开标识** | 贴出去也拿不到任何东西 | 目标站域名（`hark.com` / `auth.hark.com`）、API 路径、免费额度数字（8M tokens/天）、业务错误码、`cfat_` 这个**前缀**本身 | **可以**留默认值，但注释里必须写明"为什么它不是秘密" |

🔴 **分类不是一次性判断**：`cfat_` 前缀今天是 🟢（它只是各家 token 的公共前缀），
但某个**具体的** `cfat_xxx…` 是 🔴。**同一个字符串，前缀与取值可以是两个分类。**

### 本项目特有的两处判断

* **邮箱地址在台账里是明文，在终端里打码。** 台账（`ledger/`）是账号的**唯一副本**
  —— 邮箱是临时邮箱、收不到找回信，密码只存在那里 —— 所以它必须存明文；
  而终端输出过 `redact.redact_email()`（保留域名、抹掉本地部分）。
  两者不矛盾：**一个是数据，一个是日志。**
* **出口 IP 属于"只打印、不落盘"**：`run.py` 启动时会按槽位打印出口 IP（那是排查
  必需的），但仓库里任何地方都不写它，`.env` 里也只是「端口=IP」的映射。

## 2. 代码规范

1. 🔴 / 🟠 / 🟡 类标识**只走环境变量**（`common/config.py`），**默认空**。
   缺失时由 `config.validate()` 在**启动阶段**报错并给出修法 —— 不要让它跑到一半才炸
   （那时的报错会指向"401"或"域名不对"，离真因很远）。
2. 🟢 类标识可以带默认值，但**必须在注释里写明分类理由**。仓库里现成的例子：
   `HARK_BASE` / `AUTH_BASE`（目标站域名）与 `_PW_*` 密码字符集。
3. **错误文案里不得回显凭据**。`src/redact.py` 是唯一实现；凡是把配置值/URL 写进
   stdout、日志、台账的地方，先过它。
   ⚠ 已知的例外是**邮箱**：台账存明文（见上），但报告层必须打码。
4. **不要"顺手"加默认值**。一个看起来无害的默认（比如工具里写死一个自有域名当兜底）
   正是本次审计抓到的形态：它既泄漏标识，又让工具**静默做错事**
   （`probe_domains.py` 拿不到域名时去探一个写死的域名，报告看起来正常但与配置无关）。

## 3. 文档规范

* 需要举例时用**占位符**：`<your-mail-domain>`、`<worker>.<sub>.workers.dev`、
  `<账号邮箱>`。**不要把真实值写进文档再"提醒自己不要提交"** —— 提交是默认动作。
* **实测结论要写方法与边界**（`docs/README.md` 的约定），但**结论里不出现真实标识**：
  "自有域名直接过" 就够了，不需要写出是哪个域名。
* 终端输出规范：出口 IP 可以打印（排查需要），但**那段输出不要粘进任何仓库 / issue**。

## 4. 目录规范

| 目录 / 文件 | 内容 | 为什么 |
|---|---|---|
| `ledger/` | 账号台账（明文邮箱 + 密码 + session token） | 唯一副本；**按目录** gitignore |
| `state/` | 本地计数、探测报告、备份 | 运行期产物，含真实标识 |
| `.env` | 全部 🔴/🟠 标识的真实值 | 唯一允许落盘的凭据文件 |
| `build/` `dist/` `*.egg-info/` | 构建产物 | 验证一次构建就会多出来（实测踩过） |

🔴 **按目录排除，不靠 `*.json` 通配兜底**：通配符一旦被某个 `!` 例外打穿，
泄漏的就是整本账号。这条由 `tests/test_repo_hygiene.py` 断言（真的跑
`git check-ignore`，而不只是读一遍 `.gitignore` 文本 —— 后者是**自证**）。

## 5. 闸门：怎么保证规范被执行

规范只要靠"记得"，就一定会被违反（本次审计就是证据）。所以每条规则都落成一个检查：

| 检查 | 落点 | 覆盖什么 |
|---|---|---|
| 已知凭据**具体值** | `test_no_credentials_in_repo_files` | 那两个真实 token |
| 凭据**形状**（`cfat_`/`sk-`/`ghp_`/`AKIA`/私钥块…） | 同上 | **下一个**新凭据（只认具体值的闸门拦不住它） |
| 检测器**真的会拦吗** | `test_credential_detector_actually_fires` + CI 的变异自检 | 防"恒 `exit 0` 的死检查" |
| 🟠 标识**不出现** | `test_no_infrastructure_identifiers_in_repo_files` | Worker 子域 / 收信域名 / 出口 IP（值从本地 `.env` 读，见下） |
| 本机绝对路径 | `test_no_absolute_paths_in_repo` | `X:\…` 形态（跨机器无意义，且暴露目录布局） |
| 敏感目录真的被忽略 | `test_gitignore_actually_ignores_the_ledger` | 真跑 `git check-ignore` |
| 文档齐备 | `test_docs_exist` | README / protocol / 本文件 / `.env.example` |

⚠ **🟠 那一条在 CI 上是空转**：它的判据值来自本地 `.env`（`HR_WORKER_DOMAIN` 等），
而 CI 上没有 `.env`（它是 gitignored 的），所以拿不到值可断言。
这不是缺陷，是**边界**：CI 无法知道"什么值对你而言是敏感的"。
⇒ **它不能替代人工分类**，只能在你本地跑测试时把"顺手写进去的真实值"当场拦下。

## 6. 事故处置

**轮换清单**（哪一个泄漏了就换哪一个）：

| 泄漏的 | 要换什么 | 额外动作 |
|---|---|---|
| CF Worker Admin Token | Worker 的 `ADMIN_TOKEN` secret | 换完确认 `/api/inbox` 仍 200（别把邮箱链打断） |
| CF 账户级 API Token | 重新签发 | 检查 D1 有没有被读过（`cf_service_doctor.py` 看 rows_read 曲线） |
| 邮箱域名 / Worker 子域 | 换域名 / 换 Worker 名 | 换域名后要重跑 `probe_domains.py`（有的域名收不到 hark 的信） |
| 出口 IP | 换节点 | 换完重跑 `probe_slots.py`（出口必须两两不同，否则池子白加） |
| 账号密码 / session | 逐个改密 | 用 magic link 重设（账号还在的话） |

🔴 **`git rm --cached` 不等于删除**：文件仍在历史里，`git log -p` 照样能看到。
真正的补救是**轮换**（假设它已经泄漏），外加改写历史（而改写历史要求所有人重新克隆）。
所以顺序永远是：**先轮换，再谈历史。**

## 7. 本次审计发现并修掉的违规（2026-10-08）

写这份文档时顺手对**已提交的树**做了一遍分类审计（`git grep`，不是扫工作区 ——
后者会连 `ledger/`、`state/` 这些 gitignored 目录一起算进来，得出假结论）：

| 违规 | 处数 | 修法 |
|---|---|---|
| 收信域名（🟠）出现在 README / protocol / config / redact / 测试里 | 16 | 换成 `<your-mail-domain>` 占位符；测试改用 RFC 2606 的 `example.com` |
| 另一个自有域名（🟠）出现在 README / protocol / probe_domains | 5 | 换成"自有域名" |
| **具体账号地址**（🟠+🟡）被写成 `repair_stages.py` 的默认目标 | 2 | 该工具改成 `--email` **必填**（工具本来也不该"默认改某一条记录"） |
| `probe_domains.py` 里写死自有域名当兜底 | 1 | 删掉兜底，拿不到域名就**大声报错**（静默探一个写死的域名是更坏的失败） |
| 本机绝对路径（🟠）出现在 pyrightconfig / 测试注释 | 2 | 改成"本仓库的父目录" |

**这次审计暴露的通用教训**：5 类违规里有 4 类**不是**"忘了加 gitignore"，
而是"**在注释、文档、默认值里顺手写了真实值**" —— 那正是闸门最难覆盖的地方，
因为写的人当时想的是"这样更具体、更好懂"。所以 §5 里那条"🟠 标识不出现"
的检查是从本地 `.env` **反推**真实值来断言的：它能拦住"顺手"，拦不住"分类错误"。
